# Content Specification

This document defines all portfolio content and how it should be organized throughout the application.

Content should remain concise, outcome-focused, and easy to maintain.

Whenever possible, content should emphasize business value over technical implementation.

# Featured Project

Only one project should be featured.

Purpose:

Immediately demonstrate the strongest example of engineering work.

The featured project should include:

- Name
- Thumbnail
- Summary
- Business Problem
- Solution
- Technologies
- Architecture
- Challenges
- Results
- Screenshots
- GitHub
- Live Demo

The featured project may also appear inside the Projects view.

---

# Projects

Every project should follow the same structure.

Required fields:

- ID
- Title
- Category
- Thumbnail
- Gallery
- Short Description
- Business Problem
- Solution
- Key Features
- Tech Stack
- Development Status
- GitHub URL
- Live Demo URL
- Featured (Boolean)

Optional fields:

- Architecture Diagram
- Lessons Learned
- Future Improvements

Projects should focus on outcomes before technologies.

# Writing Guidelines

Content should:

- Be concise.
- Prioritize business outcomes.
- Avoid unnecessary buzzwords.
- Be written in first person where appropriate.
- Remain technically accurate.
- Be easy to skim.

---

# Tone of Voice

Professional

Confident

Approachable

Technical

Practical

Avoid sounding overly corporate or overly casual.
